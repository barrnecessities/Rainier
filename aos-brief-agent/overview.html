How the pieces fit together

Six layers, one run. Each layer feeds the next — and two of them (type and posture) are the only choices a user ever makes.

Type+ Posture+ Data→ Narrative→ Modules→ QA→ Brief
1

Brief Type

— picked first. Decides how every question below is phrased and which module set the brief ends with.
Click a type — the pillar phrasing and module grid below switch to match.
type unlocks the data pull & phrases the pillars
2

Posture

— one lens per run. Reweights emphasis, tone and depth. Never changes what exists — only what gets deepened vs. compressed.
Hover a posture — watch the module grid at layer 5 light up (deepened) and fade (compressed).
both selections scope what data gets pulled
3

Source Channels

— every input carries exactly one tag. Pillars read them in priority order (e.g. CLIENT → AOS → USER). Nothing is ever fabricated.

CLIENT

Uploaded reference docs: brand voice, segments, product truths, legal disclosures, prior performance.

The Central Narrative

— written once, before any module exists. This is what keeps the brief coherent.
"The narrative is written once so the brief stays consistent; postures reweight it and versions shift emphasis — the module set per brief type stays the same."
the narrative projects into the type's fixed module set
5

Modules

— the output sections. Fixed list per type; always derived from the narrative, never written independently.
Hovering a posture above highlights what it deepens (purple) and compresses (faded).
nothing ships until every check passes
6

QA Gate

— blocking. Auto-revises up to 2×, then escalates to a human with the failed checks attached.
✓ QualityComplete, grounded, nothing fabricated — every figure traces to a named source. Gaps flagged "client to provide."
✓ PostureThe selected lens holds throughout — right modules deepened, no off-posture drift, reader-appropriate vocabulary.
✓ ConsistencyOne coherent brief — numbers reconcile everywhere, no module contradicts another, terminology uniform.
⚠ On any failure: the brief is not released. Revise → re-scan → (after 2 fails) escalate to a human Worker.

The four rules that make it hang together

1️⃣
Type first. The brief type is known before context assembly — it phrases the pillar questions and scopes the data pull.
📖
Narrative first. One story is written across the pillars before any module exists. Modules are projections, never independent.
🔍
Posture reweights, never restructures. Same content, different lens — deepen and compress, not add and remove.
🚧
QA blocks. Only a fully passing scan releases the brief. Genuine gaps ship as explicit flags, never silent filler.
